我的意见：**进程内缓存**。100 人的量级，Redis 多出一个要部署、监控、排障的服务，收益很小 🤔

```
服务跑几个进程？
├── 1 个进程
│   → 进程内缓存（加 TTL 过期）
├── 多个进程，数据短暂不一致可接受
│   → 仍用进程内缓存，TTL 设短一点
└── 多个进程，要求强一致，或缓存要撑过重启
    → 上 Redis
```

- **TTL**: 字典必须带过期时间和大小上限，否则会无限增长。我没看你的代码，猜你用 Python 的话，`cachetools.TTLCache` 现成可用。
- **代价**: 重启后缓存清空，多进程各存一份。内部小工具通常没问题。
