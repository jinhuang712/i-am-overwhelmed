先排查，再决定要不要上 Redis：

```
接口慢吗？
├── 不慢
│   → 不上 Redis，保持简单 ✅
└── 慢
    ├── 慢在 SQL
    │   → 先加索引、改查询
    ├── 慢在调外部 API
    │   → 先用进程内缓存（如 LRU）
    └── 以上都试过，或要多实例共享缓存、session
        → 这时再上 Redis
```

值得上 Redis 的 3 种情况：

- **多实例共享**：你们部署了多个实例，需要共享 session 或缓存。
- **外部调用贵**：某个外部 API 很慢，或者按调用次数收费。
- **已经有 Redis**：公司已有托管 Redis，接入几乎没有运维成本。

> 100 人用的工具上 Redis，常常是在给不存在的流量做准备 😄
